# Ultra EVM Testnet collection cleanup

The authenticated wallet registered on a Testnet listing can withdraw it from
LookeNFT even when Ultra RPC is unavailable. The current on-chain owner can
also withdraw it after a live ownership check. In Explore or Manage Collection → Owner, type
`DELETE <collection name>` to enable **Delete collection from LookeNFT**.

* Deleting is a reversible **database archive**: the collection disappears from
  public Explore, direct collection pages and the LookeNFT NFT gallery. The
  operator can still access the saved contract URL while signed into the
  current contract owner wallet and **Restore collection as private draft**.
* Individual ERC-721 NFTs can be **hidden from the LookeNFT gallery** only
  when the collection owner currently owns that token too. A signature-authenticated
  request confirms `owner()` and `ownerOf(tokenId)` against Ultra EVM Testnet.
  If a hidden token transfers to a new owner, its public visibility returns.
  The collection owner may restore any hidden token.
* Neither action burns NFTs, destroys deployed contracts, changes wallet balances,
  clears on-chain history, or stops an already-scheduled on-chain mint phase.
  Existing Looke721Collection / Looke1155Collection deployments have no
  burn endpoint, and a frontend button cannot add one retroactively.
* Migration: `db/migrations/013_testnet_collection_cleanup.sql` must be applied
  to the target database **before enabling the new application deployment**.
* Do not run destructive SQL against `nft_collections`, canonical indexed
  transfers, or mint receipts. Those records remain verifiable. No automated
  wallet transaction is generated by any cleanup control.

Release: authenticated Preview → migration → tests and manual owner/non-owner
acceptance → production only after approval and verification.
